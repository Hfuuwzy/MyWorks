# MyWorks 全站和风改版规格

> [!WARNING]
> **历史归档（2026-07-15）**：本文保存改版前期规格，部分路由文件名、主图焦点和验收描述已被后续实现取代。当前事实以根目录 `README.md`、`DESIGN.md`、`docs/ARCHITECTURE.md`、当前代码和测试为准；文中的 Superpowers 相关流程不再构成现役要求。

## 1. 目标

将现有 Nuxt 4 个人门户从常见的后台式卡片布局改造为以 deaimon.jp 与用户标注稿为合同的和风内容门户。全站统一采用右侧可折叠导航、画面主导首页、和纸材质、竖排分类和按时间排列的文章流，同时保留现有内容分类与 Nuxt Content 数据。

## 2. 范围

### 包含

- 全站共享布局与右侧折叠导航。
- 首页首屏、分类入口、最新文章流和关于摘要。
- 博客分类页与文章详情页。
- 项目、电影、动漫、音乐、工具、生活、笔记和关于页的统一视觉改造。
- 搜索、主题切换、国际化入口的视觉整合。
- 桌面、平板、手机响应式行为。
- 参考站图片的开发期本地临时使用。

### 不包含

- 新增后台管理系统。
- 改变 Markdown 内容格式或迁移内容存储。
- 复制参考站品牌 Logo、角色名称、专有文案。
- 将参考站素材作为最终生产素材长期发布。

## 3. 参考图解读

### 首页参考图

- `H-01` 左上：替换为 MyWorks 品牌文字，保持大尺寸墨迹书法感。
- `H-02` 中左：显示最新文章或站点更新，不使用静态广告文案。
- `H-03` 左中：显示现有八个分类，使用竖排分栏。
- `H-04` 左下：保留媒体/精选内容位置；无内容时显示带细线边框的和纸占位，不能完全空白，也不能显示虚假的播放按钮。
- `H-05` 右侧：80px 固定导航轨，中央三竖线点击展开。
- 主图：使用 `文章底片.png` 作为临时背景，真实 DOM 文案覆盖其上。

### 侧边栏展开参考

- `N-01` 展开层从右向左覆盖约半屏，左侧首页仍部分可见。
- 分类采用竖排文字，每一列可点击跳转。
- 关闭按钮与触发按钮占据相同视觉轴线。
- 抽屉背景是带轻微纸纤维的暖白，不使用纯白玻璃拟态。

### 下滑内容展示排版

- 区块标题为朱红印章 + 拉开字距的英文标题 + 中文副标题。
- `F-01` 与 `F-02` 共同承载文章；文章以日期和标题为主，点线分隔，按时间倒序。
- 桌面双栏利用留白和淡色纹样保持平衡；移动端改为单栏。

导航顺序：

2. 博客文章

|---|---|---|

## 5. 页面设计

### 首页 `/`

1. 全屏主视觉。
2. 左侧品牌、更新、分类和媒体预留位。
3. 右侧折叠导航轨。
4. 下滑后的 `INFORMATION` 文章流。
5. 项目/关于摘要。
6. 简洁页脚。

### 博客 `/blog`

- 分类页标题区。
- 文本筛选器。
- 日期倒序文章时间线。
- 搜索结果与列表使用相同文章行组件。

### 文章 `/blog/[slug]`

- Content 文档只保存无语言前缀的 canonical path。默认语言直接使用 `route.path`；日语路由先从 `route.path` 剥离开头的 `/ja`，再使用 `queryCollection('blog').path(contentPath).first()` 获取文章。
- 所有文章链接先读取文档 `path`，再通过现有 i18n locale path helper 生成当前语言 URL；日语页面因此链接到 `/ja/blog/<slug>`，但查询仍命中 `/blog/<slug>`。
- 未找到时返回 Nuxt 404。
- 渲染标题、日期、分类、标签、封面和正文。
- 提供上一篇/下一篇与返回博客。

### 其他分类页

- 共享 `CategoryLanding` 布局。
- 有内容时显示时间线或开放式图文列表；无内容时显示带纹样的说明，而不是空白卡片网格。

### 关于页

- 大幅视觉与个人简介并置。
- 技能和经历改为细线时间轴，不使用九宫格卡片。

## 6. 数据流

- 分类数据抽到单一配置源，首页竖排分类和右侧导航共同使用。
- 文章仍来自 Nuxt Content `blog` collection。
- 首页按 `date DESC` 获取文章并拆分为主时间线与次时间线，两栏不得重复。
- 拆分算法：排序后索引为偶数的文章进入 `F-01` 左栏，索引为奇数的文章进入 `F-02` 右栏；移动端恢复为原始排序后的单一数组。
- 搜索继续在现有文章字段中执行，不新增搜索服务。
- 文章详情通过 Content 3 `path` 查询。

## 7. 组件调整

### 替换

- `LayoutSidebar` → `RightNavRail` + `RightNavDrawer`。
- `LayoutHeader` → 合并为导航轨辅助操作；普通页面只保留必要的页面标题工具。
- `HeroSection` → `HomeVisual`。
- `CategoryGrid` → `VerticalCategoryNav`。
- `LatestPosts` → `ChronologicalFeed`。

### 保留并重构

- `SearchBar`：外观重做，查询逻辑保留；桌面和移动端均只在展开抽屉底部出现。
- `ThemeToggle`：桌面和移动端均只在导航抽屉底部出现，不在固定窄轨重复渲染。
- `LocaleSwitch`：与搜索、主题控件组成抽屉底部工具组；切换语言时保留当前页面的对应 locale path。
- `ScrollToTop`：改为朱红印章式按钮。
- `ContentCard`：仅在需要图文展示的页面保留；文章列表改用 `ArticleRow`。

### 新增

- `PaperSectionHeading`
- `ArticleRow`
- `ArticleProse`
- `CategoryLanding`
- `PatternDecoration`

## 8. 素材计划

- 首页主视觉：将 `reference/images/文章底片.png` 复制为 `public/images/reference/deaimon/hero-main.png`，统一纳入临时素材目录。
- 参考站纸张、导航背景和装饰纹样：开发期下载至 `public/images/reference/deaimon/`。
- 参考站其他人物与场景图：仅作为用户要求的临时填充图，记录来源，禁止热链。
- 所有素材位必须有稳定的 `aspect-ratio` 与裁切焦点，以便后续无代码替换。
- 主视觉裁切：桌面 `object-position: 50% 34%`，平板 `58% 38%`，手机 `72% 42%`；使用 `object-fit: cover`。
- 临时素材清单写入 `public/images/reference/deaimon/ASSET-SOURCES.md`，包含文件名、来源 URL、页面用途和正式替换状态。
- 开发预览验收允许使用清单内素材；生产素材验收要求页面对该目录的网络请求数量为 0。

## 9. 交互验收

1. 导航轨在所有页面固定于右侧。
2. 点击菜单后抽屉从右侧平滑展开，分类均可导航。
3. Escape、遮罩点击和关闭按钮均能关闭抽屉。
4. 抽屉开启时焦点不进入背景页面。
5. 首页向下滚动可看到按日期排列的文章。
6. 点击文章进入 `/blog/<slug>`，不再产生 Vue Router 无匹配警告。
7. 搜索结果使用相同有效文章路径。

## 10. 响应式验收

- 1440×900：首屏比例与标注稿一致，右侧轨为 80px，抽屉约占半屏。
- 1280×800：品牌与分类不遮挡主要人物面部。
- 768×1024：抽屉约占 72vw，内容无水平滚动。
- 390×844：固定右侧 56px 窄轨、全屏抽屉、单栏文章流、触摸区域 ≥44px。
- 375×667：首屏核心品牌、最新更新和菜单触发器均在首个视口可见。
- 两个手机视口中，前景女孩双眼和右上男性面部必须完整可见，品牌与更新文案不得覆盖面部。

## 11. 可访问性与性能

- 菜单完整键盘支持，状态通过 ARIA 公开。
- 普通文字对比度 ≥4.5:1。
- 图片提供替代文本和固定尺寸，避免 CLS。
- 首屏图片使用优化格式与响应式尺寸；非首屏图片延迟加载。
- 动画仅使用 transform/opacity，支持 reduced motion。
- 结构性图标使用统一 SVG，不使用 Emoji。

## 12. 验证计划

1. `npm run build` 验证类型、Content collection 和 SSR 构建。
2. Playwright 覆盖路由清单中的默认语言路径、`/ja` 首页、一个日语分类页，以及三篇文章详情。
3. 检查导航关闭、展开、键盘、移动端状态。
4. 在 1440、1280、768、390、375 五种视口生成截图。
5. 对首页关闭态、首页展开态和下滑文章区分别与 `首页参考图.png`、`侧边栏展开参考.png`、`下滑内容展示排版.png` 比较。右侧轨宽误差 ≤1px；桌面抽屉宽度必须处于 `48vw` 且受 560–760px 约束；首屏高度必须等于视口高度；结构性热点区域不得出现超过 35% 的差异率。由于文案和品牌不同，总体相似度只作诊断，不作为单一通过条件。
6. 双 Oracle 定义：A 负责设计系统、DOM 真实性、功能和响应式；B 负责参考图区域级视觉匹配、中文/日文换行和字体精度。A、B 均须 `PASS` 且无 blocking 项。
7. 可访问性自动/手动验收：
   - Tab 聚焦菜单按钮后按 Enter，焦点进入抽屉首个链接；连续 Tab 不得离开抽屉；Escape 关闭后焦点回到菜单按钮。
   - 读取抽屉 DOM，导航项语义顺序必须与 §4 一致，视觉 `writing-mode` 不得改变屏幕阅读顺序。
   - 对正文、次要文字和交互控件计算 WCAG 对比度：正文 ≥4.5:1，大字与图形 ≥3:1。
   - Playwright 启用 `reducedMotion: 'reduce'` 后，抽屉和页面装饰的动画时长必须为 0.01ms 或 `none`。
   - 所有内容图片 `alt` 非空；装饰纹样 `alt=""` 或使用 CSS 背景。
   - 桌面、平板和手机 DOM 中，搜索、语言与主题控件各只能存在一个可交互实例，且都位于展开抽屉底部工具组。
8. 深色主题验收：在 1440×900、390×844 各截图首页关闭态和文章详情；布局尺寸与浅色主题一致，正文对比度 ≥4.5:1，导航和分隔线可辨识。
9. 素材验收分两级：
   - 开发预览：临时素材均存在于清单且无热链请求。
   - 生产素材：浏览全部路由时，对 `/images/reference/deaimon/` 的请求数必须为 0；该检查显式包含临时首页主图 `hero-main.png`。

## 13. 完成标准

- 三张标注稿中的全部红框要求均有真实 DOM 对应物。
- `H-01` 至 `H-05`、`N-01`、`F-01`、`F-02` 均通过逐项核对。
- 全站不再出现旧左侧栏、后台式顶部栏或三列文章卡片墙。
- 所有分类、搜索和文章链接可用。
- 页面视觉可追溯到 `DESIGN.md` 令牌和组件合同。
- 开发预览完成时，临时参考站图片有清单且不热链；只有临时素材请求数为 0 时才能声明生产素材就绪。
